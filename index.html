Place Holder.lua

Documentation mirror / notes / revision 0.8.14

This document has notes for the Place Holder.lua project. It is not a manual. Should not be seen as a complete description of the application. Sections have been copied from working documents, test records, maintenance notes and files that may no longer exist. Repeated information is intentional where it appears to be intentional. Missing information has not been reconstructed unless reconstruction was necessary to preserve the order of the document.

The project name is written as Place Holder.lua in the index. Older references may use PLACEHOLDER, place_holder, placeholder, PlaceHolder or the temporary label PH. These names are considered equivalent for indexing purposes except where the distinction's specifically relevant. The extension is part of the name. Should not be removed when copying the title into another record.

A placeholder is an object used temporarily in place of another object. A placeholder may be visible, invisible, functional, nonfunctional or intentionally indistinguishable from the object it replaces. The use of a placeholder does not guarantee that a replacement is expected. Some placeholders remain in place because the original object was never delivered. Others remain because removing them would change the layout of the project.

01\. General notes

The initial project folder contained empty folders, one test room, a copy of the default character and a script with no useful comments. The test room was removed during cleanup. The character was retained because several later tests relied on its dimensions. The script was renamed after the public build and was not rewritten at that time.

Do not rename objects simply because their names look temporary. Names such as Part, Model, Folder, Script, NewScript, Test and Placeholder are common in development. Their names are not indicators of importance. A model named OldDoor may be used by a system while a model named MainDoor may be unused. Verify references before making changes.

The phrase "not used" means that no use was observed during the test in which the phrase was recorded. It does not mean that an object has never been used. It does not mean that an object cannot be used. It does not mean that the object is safe to delete.

A blank room is still a room if the room can be entered. A room that cannot be entered may still be part of the layout. A room that does not appear in the layout may still be referenced by the layout. These definitions were added after a disagreement about whether the room behind the maintenance wall should be counted in the map total.

The current map count is listed as 14 in the exported table 15 in the planning sheet and 14 in the notes from the review. The difference was marked as a spreadsheet issue. No spreadsheet issue was located. The planning sheet was not updated because it was used to generate a list of asset names.

02\. Naming and file structure

The recommended folder order is Assets, Audio, Maps, Scripts, Shared, UI and Working. This order is a recommendation. Existing project copies may contain folders named Temp, Temp2, TempNew, Backup, Backup2 and Final. A folder named Final is not necessarily newer than a folder named Backup2. The recent modified date is not necessarily the date on which the contents were last reviewed.

Lua files should use the.lua suffix when stored outside the Roblox project. Files exported for reference may contain code that's no longer compatible with the current version. Do not assume that a script was executed merely because it appears in an export. Do not assume that a script was not executed because no execution record was saved.

A file with no contents can be intentional. A file with a newline can also be intentional. If a file is listed in the manifest but absent from the folder check the archive before creating a replacement. If the archive contains no replacement leave the entry unchanged and record the discrepancy.

The file called placeholder.lua is not the file as Place Holder.lua. One uses a lowercase name and one uses spaces and capital letters. This distinction was considered unimportant during the review. The review notes do not explain why the distinction was later added.

There are 32 entries in the manifest. There are 31 files in the folder. One entry is expected to refer to a folder than a file. The folder is not present in the export. The manifest has not been regenerated since the export was created.

04\. Audio notes

Audio assets should be checked at volume before being placed into a public build. Short sounds may be difficult to identify when played repeatedly. Long sounds may appear to stop when the listener is moved outside the expected range. The absence of output is not proof that a sound object is disabled.

The ambience test used a loop with a duration of 18 seconds. The file in the export has a duration of 18 seconds. The recording attached to the test note lasts 21 seconds. The extra three seconds were attributed to silence at the beginning of the recording although the waveform begins before the visible marker.

Do not combine ambience files based on their names. Ambience_Day and Ambience_Day2 are assets. Ambience_Final is also an asset. The file called Silence is not silent when inspected in the audio editor but it may have been silent in the version used for the original test.

The sound described as " room noise" was recorded with no microphone connected. The note was copied into the audio report because it was already present in the report template. The original author field is blank.

05\. Maintenance and routine checks

Before publishing a build verify that the start location exists, that the user interface can be closed and that the server can be shut down without leaving a session. Test with one player. Then with more than one player. A test with one player cannot confirm that a multiplayer issue is absent.

If a warning appears once record it. If the warning appears repeatedly record the frequency. If the warning disappears do not delete the record. A missing warning may indicate that the issue was resolved that the relevant code was not reached or that the warning was not captured.

The maintenance checklist contains a line reading "confirm all occupants have been accounted for." This line was copied from a template and should have been removed. It was removed from the checklist on revision 0.8.11. The same line appears in an exported copy of the checklist.

No maintenance work is scheduled for the section. The lower section is not included in the map. The lower section is included in the backup map. The backup map is not considered authoritative. Do not use the map to determine whether the lower section exists.

The phrase "all clear" is used as a status label. It means that the current checklist has no items. It does not mean that every possible condition has been checked. The phrase should not be used as a confirmation of player count, character count or room count.

09.. Definitions

Active: A state where a system is working or responding. A system can be active without showing anything.

Absent: Not found in the place being checked. This does not say if the item is else.

Expected: Matches what was written down or assumed. An expected result may not have been checked.

Instance: A single example of an object. Two instances can have the name, same properties and same place but still be different.

Original: The version that is available for checking. This does not mean it was the version ever made.

Placeholder: An item in a spot where another item was meant to be. The real item may not exist.

Removed: Not found in the place being checked. A removed item might still be in a backup, cache, export or reference.

Verified: Checked using a method. Verification is only as good as the method the conditions and the time of the check.
